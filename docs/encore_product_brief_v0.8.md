## 1. 产品介绍

**一句话总结**: Encore 把 TikTok 游戏直播里"只能看"的观众变成"也能玩"的玩家 —— 不打扰主播打游戏的前提下, 把每个高光时刻自动变成 30 秒可玩小游戏, 让观众、主播、平台三方都拿到价值: 观众多了参与感和自己的短视频, 主播多了被动产出和打赏入口, 平台多了新 UGC 内容池和 install 漏斗。

### 1.1 真问题

TikTok 游戏直播现在有这些功能让观众跟主播互动:

| 现有功能 | 观众能做什么 | 不够在哪 |
|---|---|---|
| 送礼物打赏 | 单向给主播打钱 | 没操作感、心智门槛高 |
| 刷弹幕评论 | 打字 | 单向、信息密度低 |
| 关注 / 加群 | 长期决策 | 0/1 切换,没中间档位 |
| **礼物互动小游戏**(PUBGM / 蛋仔联动)| 送礼影响主播游戏 | **代价是主播变 MC 不再认真打,把游戏直播本身给毁了** |
| Polls / 投票 | 选选项 | 互动频率低、赚不到钱 |
| 游戏竞猜 | 押注主播 | 完全二手体验,没操作感 |

**结论**: 观众"自己也想动手玩一下"这个需求, 在所有现有功能里都没解决。

> 注: v0.7 写过"5 秒高光黑洞 + 3.5s 弹幕延迟"这些数字, 查不到来源, 已删。 这一节的逻辑不依赖任何具体数字。

### 1.2 Encore 站在哪里

Encore 不是替换上面任何一个功能, 而是**多开一个维度**: 让观众自己上手玩, 但不影响主播打游戏。

跟现有功能并列对比:

| 功能 | 主播在干嘛 | 观众在干嘛 | 影响主播吗 |
|---|---|---|---|
| **互动游戏**(萌宠快跑等新建设)| 化身游戏角色, 被观众礼物驱动加速 / 撞障碍 | 送指定礼物触发预设游戏内特效 | **高**(整个 loop 依赖主播被礼物驱动)|
| **弹幕游戏** | 反应 + 接事件 | 发弹幕 / 送礼影响事件 | 中 |
| Polls / 投票 | 提问 | 投票 | 无 |
| 游戏竞猜 | 被押注 | 押注 | 无 |
| 弹幕 / 礼物(纯表达)| 反应 | 表达 | 无 |
| **Encore** | **继续打 ranked,什么都不变** | **自己上手玩 30 秒小游戏** | **零** |

### 1.3 一条最重要的硬规则: 不打扰主播打游戏

> **主播玩什么、怎么玩、什么时候玩, Encore 永远不动。 Encore 是给观众的, 不是给主播的工具。**

这条规则具体意味着:

- ❌ "送礼物让主播下一把开 buff" — 不做
- ❌ "Sponsor 主播下一局" — 不做
- ✅ Enhance(改观众自己的下一局)— 做
- ✅ 主播只看通知, 不需要做任何操作

这条规则是 Encore 跟现有礼物互动小游戏的根本区别。 已经锁死在附录 A。

### 1.4 这个产品对谁有价值

- **观众**: 看到高光想动手时有出口, 不只是干刷弹幕。 进前 3 名自动生成一条短视频发到自己 TikTok, 变成自己的内容
- **主播**: 多一条被动产出短视频的渠道(玩家拿前 3 自动 @ 主播 + 联名), 多一种打赏入口, 但完全不打扰自己打 ranked
- **平台**: 填上"观众也能玩一下"这个空白, #Encore 标签下的短视频是 TikTok 算法可以吸收的新内容池, 内嵌"Play [游戏名]"按钮是天然的游戏发行漏斗

具体能拉升多少停留时长 / ARPU / 付费率, **第一版不预设结论**, 灰度数据出来再说。

### 1.5 第一批要服务谁

**第一版灰度(核心用户)**:

- TikTok 游戏直播头部主播(FPS / MOBA / 吃鸡品类, 粉丝 ≥ 50w): 5-10 人启动
- TikTok 游戏直播重度观众(每日看直播 ≥ 30 分钟): 付费意愿和分享意愿双高

**之后再扩**:

- 中长尾游戏主播(粉丝 ≥ 5w)
- 跨品类直播(派对、卡牌、IRL 等需要观众互动的赛道)
- 短视频 feed 入口(M12+, 先验证直播形态成立)

## 2. 用户怎么用

### 2.1 主播侧

**开播前在主播 dashboard 配一次(以后都不用动)**:

```
[Encore 开关]
  · 灰度阶段:默认开(BD 一对一沟通过,知情)
  · 全量阶段:默认关,主播主动开

[联名自动接受]  (只有开 Encore 才显示)
  · 默认开,可以关
  · 开 = 玩家拿前 3 的短视频自动以联名形式发布(主播零操作)
  · 关 = 短视频只 @ 主播,不联名,主播之后可手动决定每条

[Enhance 礼物门槛]
  · 候选:关(推荐)/ 50 金币 / 200 金币 / 500 金币
  · 关 = 玩家直接付费买 Enhance
  · 设了门槛 = 玩家要先送给主播 N 金币,才能买 Enhance
  · 超过 500 金币时 dashboard 出软警告"这门槛会让你少赚 X%"
```

**直播过程中**:

```
AI 识别到高光时刻
  ↓
推送一个通知到主播端 (5 秒倒计时)
  · 默认 promote (放出 Encore)
  · 主播可一键 skip (本次不弹给观众)
  · Vision 成本已经花了,跳过只是不弹
  ↓
promote → 屏幕底部 Encore 小窗弹给所有在场观众
skip → 这次不弹,等下次高光
  ↓
主播继续打 ranked,完全不被打扰
```

**直播结束后(异步, 主播零操作)**:

- 前 3 名玩家的短视频渲染完(~3-5 分钟)后, 自动发到玩家自己 TikTok + @ 主播
- 主播完全不需要 review / 审核 / 操作
- 不喜欢某条短视频 → 走 TikTok 既有"举报 / 请求删除"通道(跟任何被 @ 的内容一样)
- 想关 Encore → dashboard 一键关
- **为什么不让主播 review 短视频**: 那就违反"不打扰主播"的硬规则。 主播打 ranked 不会有空逐条审。 信任放在三道防线上: 观众首次玩时已经同意发布、低分不发布、TikTok 平台自己有内容治理

### 2.2 观众侧

**第一次玩 Encore 时(一次性弹窗)**:

```
弹窗:
  「玩 Encore 即同意:
   · 如果进前 3 名,你的玩法会被生成一条上下分屏的短视频,自动发到你 TikTok + @ 主播
   · 没进前 3 名的局不会生成 / 不会发布,失败录像不会有任何人看到
   · 同意条款随时在设置里撤回(已发布的短视频走 TikTok 普通删除流程)」
  [同意才能玩]
```

**每次高光场(重复)**:

```
进直播间
  ↓
[看主播打 ~ 任意时长]
  ↓
AI 检测高光 → 主播 promote → 屏幕底部弹出 Encore 小窗口
  · 每场每人最多弹 3-5 次(防止扰民)
  · 永远不挡主播画面,永远不静音
  ↓
3-5 秒 "怎么玩" 卡片(教学,可一键跳过)
  ↓
玩 30 秒 Encore(玩的是刚才那个高光场面的变体)
  ↓
结果页:
  · 个人分数 + 排名
  · 实时排名 "你现在第 N 名 / 共 X 人玩过(还有 Y 人在玩)"
  · 付费入口:
    · 主播没设门槛 → 直接付费买 Enhance
    · 主播设了门槛 → 先送 N 金币给主播,然后才能买 Enhance
  ↓
高光场结束 (~3-5 分钟后异步):
  · 拿前 3 → push 通知 "你拿第 N 名,短视频已生成"
  · 没拿前 3 → 没任何通知 (失败局不弹付费)
  ↓
小窗自动滑下 → 冷却 → 继续看主播
```

### 2.3 短视频生成发布

| 怎么定 | 怎么做 |
|---|---|
| **资格** | 只有前 3 名免费自动生成。 其他名次不生成、不卖付费 clip(v0.8.1 砍了 Spotlight)|
| **排名** | 分数高的优先 → 完成时间早的优先 → 进 Encore 早的优先 |
| **谁是发布者** | 玩家自己(发到玩家 TikTok profile + 推到双方粉丝 feed)|
| **主播怎么绑** | 自动 @ 主播。 主播 30 分钟内可选择联名(可选, 不联也照发)|
| **视觉格式** | 默认上下分屏: 主播 15 秒在上 + 玩家 15 秒在下, 总长 15 秒同步播。 备选 A/B: 前后接续 |
| **玩家视频怎么剪** | 服务端自动从 30 秒玩法里剪出分数峰值附近的 15 秒 |
| **失败局** | 不生成, 不可付费补救 |
| **质量门槛** | 完成 + 最低分数 → 否则不算入前 3 |
| **分发渠道** | 跟 TikTok 普通 UGC 一样, 进 profile + 双方粉丝 feed, 自动加 #Encore 标签 |
| **算法保护** | 服务端有质量门槛防止 #Encore 标签被算法当 spam。 后续跟算法团队对齐"联名/混剪"标识 |
| **CTA** | 描述里自动嵌"Play [游戏名]"按钮, 走 TikTok game center。 不依赖厂商 BD |

### 2.4 商业营收

**铁律**: 玩 Encore / 看 winner 短视频 / 被联名 — 任何时候都不收费。 礼物门槛只能加在**付费功能入口**前。

**免费的**(永远不收费, 也是大多数观众的实际体验):

- 玩 Encore 30 秒(无限次)
- 进前 3 自动免费生成上下分屏短视频回流 TikTok
- 看任何 winner 的短视频
- 被联名(主播 Duet, 玩家被动获得曝光)
- result page 看实时排名

**付费的**(第一版就一个 SKU, 主播可加礼物门槛):

| 功能 | 价位 | 阶段 | 卖点 |
|---|---|---|---|
| **Enhance** | $0.5-1 | 第一版 | **跟街机塞币一个意思**: 改你下一局(火焰子弹 / 双倍 HP / 多一条命)→ 不甘心想再赢一把 |

**为什么第一版只有 Enhance 一个 SKU**:

- 触发时机精准: result page 看到自己没进前 3 / 进了前 3 想刷高分 → 心理动机最强
- 跟既有送礼习惯无缝衔接: 已经在 LIVE 间送礼的高活跃观众, 自然会买 Enhance
- 一句话说完: **"想再赢一把?Enhance 续命"**, 评委、BD、主播、观众都秒懂

**v0.8.1 砍掉的 SKU 和原因**:

| 砍掉 | 原因 |
|---|---|
| Spotlight(让没进前 3 的观众花 $0.5 发布自己的短视频)| 失败局没人愿意付费晒自己的失败录像。 门槛 + $0.5 套在最低动机用户上, 转化率会很差 |
| Sponsor(送礼物影响主播下一局)| 违反"不打扰主播"硬规则 |
| Loot(概率宝箱)| 赌博机制 + 监管风险 |

**第二阶段重新引入的 SKU**(详见 §4.3):

- **Remix**($2-5)— M11+ 上线, AI 根据观众一句话生成自定义参数 — 这才是 AI 真正不可替代的功能
- **Spotlight v2** — M14+, **重新设计成"挑战朋友"**(不是发布失败, 是 @ 朋友看你挑战), 需 TikTok 朋友标签基建

**主播 dashboard 设置**(简化):

- 一个开关: `Encore 礼物门槛 · 关(推荐)/ 50 / 200 / 500 金币`
- 开 = 观众买 Enhance 前先送 N 金币给主播
- 关 = 观众直接买, 主播没这笔礼物分成

**主播怎么分钱**:

- 礼物门槛触发的礼物 → 走 TikTok LIVE 正常分成(主播主要收益)
- Enhance 本身的收入 → 平台 / Encore 分成(主播不分)
- **关键边界**: 主播不分付费功能本身的收入, 防止主播为催付费主动降低礼物门槛, 导致观众体验变差

## 3. 机制设计(技术 + 业务联合)

### 3.1 前 3 名短视频生成机制

**为什么前 3 而不是只有第 1**:

- 只有第 1 名 → 玩家觉得"反正赢不过那个最强的", 不想玩
- 前 3 名 → 有 3 个槽位, 大家都觉得"我有机会"
- 数学上: 50 个高光场 × 3 名 = 150 条短视频/场, 总量可控

**怎么选前 3**:

- 完成度门槛 + 最低分数 + 验证完整按键日志
- 防 bot 农场: 设备指纹 + 玩家在 LIVE 间停留 ≥ 5 分钟 + Encore 历史指纹
- 平局规则: 分数 → 完成时间 → 进 Encore 时间(三级排序)

### 3.2 服务端怎么渲染短视频

**核心思路**: Encore 游戏是**确定性的**(同样随机种子 + 同样按键序列 = 同样结果), 所以客户端只需要把按键日志(几 KB)上传, 服务端就能重新跑一遍游戏并录像。

```
观众客户端
  · 记录完整按键日志(按键 + 时间戳,几 KB)
  · 上传到 Encore 服务端
  · 不录视频,不传视频流(移动端流量 / 电量友好)

Encore 服务端 (异步 worker)
  · 收按键日志 + session metadata (seed, 模板, 主题)
  · headless Canvas 重跑一遍 30 秒游戏,取分数峰值前后 7.5 秒 = 15 秒
  · 拉主播这边的 15 秒高光剪辑(TikTok LIVE 已有 pipeline)
  · ffmpeg 上下拼接 → 输出 9:16 短视频
  · 发到玩家自己 TikTok account,@ 主播,带 #Encore 标签

延迟:高光结束 ~3-5 分钟内短视频出来
```

**成本量级**(估算, 要工程实测验证):

- 一条短视频渲染 ≈ 0.5-1 CPU·秒
- 全量 50K 直播间 × 50 高光 × 3 名 = 7.5M 条/天
- 7.5M × 1 秒 = ~2000 CPU·小时/天 ≈ **$50-200/天**(云上 spot)
- 对比 Vision 检测(见 §6.2)成本可忽略

**Demo 阶段已经端侧打通(M8 完成)**: hackathon demo 里我们用浏览器原生 Canvas + MediaRecorder 把整条链路真的跑出来了 —— 玩家玩 30 秒, 游戏 canvas 直接被 MediaRecorder 抓帧成一段录屏, winner 时刻这段录屏再被 drawImage 到上下分屏合成 canvas 的下半屏, 上半屏是跟主播 LIVE mode 匹配的程序化 Canvas 场景, 合成 canvas 自己再被 MediaRecorder 抓帧出最终 9:16 的真 .webm 文件, 观众能下载、能通过 Web Share API 分享。 **这证明了技术可行性**;生产环境会换到上面服务端 ffmpeg 路径, 主要为了规模 + 玩家流量 / 电量友好, 不为了"是不是能做出来"。

### 3.3 Vision 检测 + 主播 5 秒选择

主播这边的 5 秒倒计时设计是**整个机制最关键**的一步:

- 默认就是 promote(放出 Encore), 主播什么都不做也工作
- 主播看到通知如果不想 promote, 可一键 skip
- 实测使用率 < 5%(预期), 不影响 95% 主播的零操作体验
- 砍掉了 30% 误触发, 改善观众体验
- 5 秒倒计时短到不打扰主播, 长到给主播看一眼的机会

主播可选另外两档(全部可选, 不开任何也不影响产品):

| 选项 | 触发方式 | 工作量 |
|---|---|---|
| 实时 skip | 5 秒倒计时窗口内一键 skip | ≤ 1 次操作, 可全程不用 |
| 预设规则 | dashboard 配: "只有 ace/clutch auto-promote" / "比赛模式静音 Encore" | 一次设定, 长期生效 |
| 赛后批量取消 | 直播结束后看 promoted 列表, 批量取消 | 异步, 不打断打游戏 |

> 历史: v0.7 把 5 秒倒计时设计成"主播是导演, 负责砍掉 30-50% 低质触发"。 v0.8 否定了 — 跟"不打扰主播"硬规则矛盾, FPS 主播交火中没空看倒计时。 v0.8 新版: 5 秒是 silent opt-out, 默认不操作 = 默认 promote。

### 3.4 法律 / 隐私同意

| 角色 | 什么时候同意 | 怎么同意 |
|---|---|---|
| 主播 | 第一次开 Encore 开关时 | 一次性弹窗 + ToS 链接 |
| 观众 | 第一次玩 Encore 时 | 一次性弹窗(措辞友好, 参考 TikTok Duet 首次开通范式)|

可以随时撤回, 撤回后已发布的短视频走 TikTok 普通删除流程。

## 4. 商业价值

### 4.1 第一版怎么赚钱

**第一版只有一个付费 SKU = Game Enhance**

| 收入项 | 来源 | 主播分成 | 平台分成 |
|---|---|---|---|
| **Enhance 礼物触发**($0.5-1)| 观众礼物赠送 | 礼物分成 | 礼物分成 |

**第二阶段以后的收入扩展**: 见 §4.3 未来怎么赚钱

**MVP 阶段要做的**:

1. 灰度 5-10 主播, 每场跑 1 周
2. 记录: Encore 触发率 / 完成率 / 付费率 / 短视频发布率 / 短视频平均观看 / 观众次日回访
3. 跟同主播开播前 1 月做 baseline 对比
4. **数据出来了再写收入模型**

### 4.2 不直接创造营收、但存在价值

- **观众停留时长**: 观众进直播间不再"看完高光就走", 还会等下一次 Encore
- **平台的 UGC 新内容**: #Encore 标签下的上下分屏短视频是 TikTok 算法可吸收的新内容池
- **主播粘性**: 接入 Encore 的主播多一条被动产出内容的渠道, 迁移到竞品时这部分内容直接归零

### 4.3 未来怎么赚钱: 三类收入

第一版只有 Enhance。 未来按 **3 大类**展开, 每一类对应一种人想付费:

#### 🅰 观众付费 — 玩得更爽

> **谁付费**: "我想玩得不一样、更爽、更厉害"

| 功能 | 描述 | 阶段 |
|---|---|---|
| **Enhance** | 改自己下一局: 火焰子弹 / 双倍 HP / 多一条命 · $0.5-1 | **第一版** |
| **皮肤 / 主题** | 角色 / 武器 / 场景皮肤(单买 + 累积解锁)| M11+ |
| **AI 自定义玩法**(Remix)| LLM 根据你说的一句话生成新参数("敌人慢一点, 武器换霰弹枪, 敌人染粉色")· $2-5 · AI 真正不可替代的功能 | M11+ |
| **升级道具** | 永久属性微提升(命中辅助 / 反应窗口 / 视野)| M14+ |
| **月卡 / VIP** | 解锁皮肤库 + 累积 Enhance 包 + 优先上前 3 | M14+ |

🅰 类是长期 LTV 阶梯, Enhance → 皮肤 → 月卡是经典手游变现路径。

#### 🅱 厂商付费 — 把这当广告位

> **谁付费**: "游戏直播本来就是天然的游戏发行漏斗, 厂商付钱买这条流量"

| 功能 | 描述 | 阶段 |
|---|---|---|
| **游戏安装归因 CPI** | 短视频内嵌"Play [游戏]"CTA, 厂商按归因安装付费 | M11+ (短视频量 ≥ 100K/天 + 厂商主动洽谈)|
| **品牌联名 Encore** | 品牌方付费 sponsor 特定 Encore 模板(类似 TikTok Branded Effect)| M12+ (跟 TikTok ad sales 中台对接)|
| **联运资源位** | 厂商在 #Encore 标签下投放主推游戏专属模板 | M14+ |

🅱 类**是第二阶段开始的主增长引擎** — 单条 CPI 规模潜力 > 所有 🅰 之和(参考 TikTok 现有 game ads 体量)。

#### 🅲 多人 / 跟主播玩 — 社交杠杆

> **谁付费**: "我想拉朋友、跟主播一起打"

| 功能 | 描述 | 阶段 |
|---|---|---|
| **挑战朋友**(Spotlight v2)| $1-2 = 自动 @ 3 个朋友"打过我看看", 社交传播 | M14+ (需 TikTok 朋友标签基建)|
| **Encore 联赛** | 主播开 Encore 联赛 + 奖金池, 观众参赛费, 平台抽成 | M14+ (头部主播运营 + 反作弊)|
| **集体送礼解锁** | 全场观众集体送礼达 threshold → 解锁主播专属 Encore 模板 | M14+ (派对玩法生态)|
| **主播同框打** | 主播开放 Encore co-play 时段, 观众跟主播同框打 | M16+ (探索)|

🅲 类转化率最低但**传播放大效应最强**, 适合 M14+ 扩盘 + 跨品类延伸(派对、卡牌、IRL 也能用)。

---

**3 大类的设计原则**:

1. **每一类对应一种用户心理, 不混**: 个体爽(A)/ 厂商投放(B)/ 多人一起玩(C)
2. **A 是长期 LTV, B 是规模主引擎, C 是社交杠杆** — 各打各的位置
3. **不做"赌博 / 抽奖 / 让礼物影响主播游戏"** — 监管 + 不打扰主播红线

**收入结构演化预期**(定性):

- M9-M10: 只有 A 类 Enhance 单核, 先验证 unit economics
- M11-M14: **A(Enhance + 皮肤 + AI 自定义)+ B(CPI + 品牌联名)双轮**, B 大概率成主增长引擎
- M14+: 加 C 类社交层, 提升传播 + LTV; A 类升级到月卡 / VIP 分层

**量化口径**:Phase 1 (Enhance 跑通) **$1.5M/月** → Phase 2 (加 CPI + 联运) **$2.0M/月** → Phase 3 (加多人玩 sponsor) **$2.1M/月**。 **净利率 95%+**(对照 §6.2 模型成本 $70-100K/月)。 完整测算 + 参数 + 敏感度见 [§6.3 收入预估](#63-收入预估对应-43-三类收入的可量化版本)。

## 5. 跟竞品比有什么差异

### 5.1 vs 现有竞品(直接同类)

| 维度 | Twitch Extensions | tikfinity | Rezone / Loopit | **Encore** |
|---|---|---|---|---|
| 怎么触发 | 观众主动开 panel | 主播配 alerts | 观众主动点 | **AI 看主播打什么自动触发** |
| 内容怎么来 | 通用预制小游戏 | 主播自配 | 通用预制 | **AI 把视频转成游戏参数, 基于主播刚才打的内容** |
| 形态 | 侧边栏(桌面优先)| 屏幕 overlay | 独立 webapp | **底部弹出(移动优先)** |
| 怎么分发 | 观众主动找 | 主播在整 | 观众在整 | **走 TikTok 主流 feed + 自动联名回流** |
| 干预主播吗 | 不 | 主播自配 | 不 | **零干预** |

**真差异化只有 2 条**:

1. **AI 看主播打了什么自动触发**(其他都是观众主动找菜单)
2. **移动优先 + 底部弹出形态**(其他都是桌面侧边栏)

> **诚实声明**: Twitch Extensions 这个品类做了 8 年没爆, 最成功的是 Predictions(不是 mini-game)。 说明 mini-game-as-extension 这个范式本身可能天花板就低。 Encore 要靠 §5.2 的差异化跳出这个天花板, 不能靠"做得更好"赢。

### 5.2 vs 互动游戏(萌宠快跑等) / 弹幕游戏

平台上跟 Encore 看起来最像的, 是「**互动游戏**」(2026 新建设, 首批接入「萌宠快跑」)和已上线的「**弹幕游戏**」。 三方在底层逻辑上其实**走不同的路**, 分清楚很重要 —— 否则容易被误认为是"另一种互动游戏 SKU"。

**互动游戏的产品形态**(来自萌宠快跑 playbook): 主播在 Windows 端 LIVE Studio 启动一款官方对接的合作游戏(目前 = 萌宠快跑), 4 位主播化身宠物在赛道上赛跑, 观众送指定礼物触发加速 / 护盾 / 撞障碍等预设特效。 主播全程要喊话、求礼物、拉氛围(playbook 配 1000+ 字"话术参考"专门教这个)。 礼物-特效映射 + 价格由官方预设, 主播不能改。

**弹幕游戏**: 类似但更轻量, 观众弹幕 / 送礼直接作为游戏输入。

三方深度对比:

| 维度 | 互动游戏 / 弹幕游戏 | **Encore** |
|---|---|---|
| **主播在玩什么** | 平台指定的合作游戏(需 mod 接入)| **任何游戏**(FPS / MOBA / 吃鸡 / GTA / Roblox 全覆盖)|
| **谁是玩家** | 主播是唯一玩家 | **每一个在场观众都能上手玩**(并行 N 路)|
| **主播怎么"参与互动"** | 喊话求礼物 + 读特效 + 拉氛围, 全程 MC | **零参与**, 主播完全可以不知道 Encore 在跑 |
| **观众怎么"参与"** | 间接(送礼影响主播游戏)| **直接**(自己上手玩 30s)|
| **适用游戏品类** | 只有官方对接 mod 的合作游戏(目前 1-2 款)| **核心游戏品类全覆盖**(TikTok Gaming 60-70% 直播内容)|
| **主播开播要求** | Windows PC + LIVE Studio + 白名单 + 下载游戏文件 / mod | **零额外动作**, 平台后台开关即可 |
| **推广路径** | 区域 LIVE Ops BD 一个个对接白名单主播 | 平台直接对全量游戏直播开 |
| **直播结束后留下什么** | 直播本身 + 营收数字 | **结构化短视频**(前 3 名自动剪上下分屏 .webm 发玩家 TikTok + @ 主播 + #Encore tag)|
| **对 TikTok feed 算法** | 无新内容池 | **#Encore 标签 = TikTok 算法可吸收的新内容池** |
| **对游戏发行漏斗** | 无 | 短视频里嵌 "Play [游戏名]" 按钮 = 天然 install 漏斗 |
| **变现模型** | 单一: 直播礼物 | 三类: 观众付费 + 厂商付费 CPI install + 多人玩社交杠杆 |
| **蚕食游戏直播品类** | **是**(主播变 MC, 核心电竞向主播无法接入)| **否**(主播照常打 ranked, 反而是品类的伴生玩法)|

**核心 framing**:

互动游戏 / 弹幕游戏的产品逻辑 = **"主播被观众影响"** —— 整个 loop 依赖主播喊话求礼物。 这种模式对**已经是娱乐主播 / MC 心智**的主播很合适, 但**核心游戏主播 / 段位主播 / 电竞向主播 接不进来** —— 这群人的核心 KPI 是打得好, 不是讨礼物。 而这群人恰好 = TikTok Gaming 流量的**大头**(FPS / MOBA / 吃鸡)。

Encore 的产品逻辑 = **"主播无关, 观众自己玩"** —— 整个 loop 在主播零参与的前提下也能转。 这让 Encore 能服务核心游戏主播这群之前没法被礼物互动覆盖的人。

**三方不是竞争, 是互补 —— 主播策略组合的三端**:

```
                 主播打游戏的认真程度  →
┌──────────────────────────────────────────────────────────┐
│ 互动游戏 / 弹幕游戏       Encore                          │
│ (萌宠快跑等专门游戏)      (任何游戏 + 观众平行玩)         │
│                                                           │
│ ← 娱乐 / MC 心智的主播    核心游戏 / 段位主播 →           │
│   全程被观众驱动            零干预 ranked                  │
└──────────────────────────────────────────────────────────┘
                 观众"自己玩"的参与度  →
```

同一个主播可以同时用两边: 打 ranked 时 Encore 在 background 跑; 想拉氛围时切到萌宠快跑专门玩一局。 同一个观众, 在两个产品里得到不同的满足: 互动游戏里"我影响了主播", Encore 里"我自己玩了一把"。

这一条是 BD / 跨团队沟通的核心叙事 —— **Encore 是保护游戏直播品类的, 不是消费它; 也不抢互动游戏的盘子, 服务的是不同人群**。

### 5.3 AI 到底必不必要

| 阶段 | AI 必需还是可替代 |
|---|---|
| 第一版的高光检测 | **可被规则系统替代**(检测击杀提示符 + 血条 + 小地图状态)。 Vision LLM 是**便利**, 不是**必需** |
| 第一版的模板选择 | **可规则替代**(按游戏 + 场景标签直接 hash)|
| 第一版的 V2G JSON 参数 | **可规则替代**(模板是预制的)|
| 第二阶段新游戏零样本扩展 | **AI 必需**(不需要重新写 OCR 就能支持新游戏)|
| 第二阶段 Remix 功能 | **AI 必需**(LLM 生成参数, 规则做不到)|

Encore 是**今天就能跑通的产品**, AI 是**第二阶段扩展性的保险**。

### 5.4 为什么是 LIVE + Gaming, 不是短视频或其他

**LIVE 的唯一不可替代性 = 同时在场**:

- 5000 个人在同一秒看到 1v3 翻盘, 弹出的 Encore 同时给 5000 人
- 共享情绪 anchor 是短视频做不到的(异步)
- LIVE 用户已经会送礼了(钱包已开), 短视频用户没开

**Gaming 的唯一不可替代性 = 高光是离散、可识别、可参数化的**:

- 聊天直播 / IRL 直播 / 唱歌直播的"高光"是连续的、主观的、没法参数化
- 只有 Gaming(FPS 击杀 / MOBA 团战 / 吃鸡残局)的高光是结构化事件

**所以 LIVE + Gaming 不是营销选择, 是唯一可行解的边界**。

## 6. 可不可行

### 6.1 技术路径

- **第一版 = 套预制模板**, 不真生成式 AI 造游戏
- AI 从视频抽 JSON 参数 → 路由到 3 套预制模板: **GTA Heist / Obby Parkour / Free Fire BR**(Mario v2)
- **抽象像素风**(Roblox / Minecraft 那种), 不碰任何游戏 IP, 千元机也能跑
- Canvas 2D + 体素方块, 不用 WebGL

详见飞书 Demo Dev Plan v0.2。

### 6.2 成本($10 万/月封顶口径,过滤层 + 阶段化 + 日预算闸门)

**核心结论**: 所有直播间先走平台已有 **高光识别 + 游戏识别** 当过滤层, 再用模板覆盖大多数高光;**模型只负责"真生成"的部分, 且按日预算自动降级**。

**关键转变**: 上一版讲的 4B 高光/月是**平台大盘**, 不是 Encore 的模型调用量。 真实算法是:**先过滤, 再模板命中, 最后只把少数高价值高光交给模型真生成**。

#### 过滤层 — 4B 大盘怎么压到 4050 万月候选

| 过滤层 | 口径 | 量级 | 为什么这么算 |
|---|---|---|---|
| 游戏主播大盘 | 90 万主播/天 | 90 万 | TikTok Gaming LIVE 的开播主播池 |
| 值得生成 Encore 的主播 | 先取 50% | 45 万主播/天 | 低观看、低互动、重复内容先不做真生成 |
| 每个主播每天触发次数 | 最多 3 次 | 135 万次/天 | 不按每小时几十个高光全放, 避免打扰观众, 也控制预算 |
| 月候选池 | 135 万 × 30 天 | **4050 万次/月** | Encore 决定"模板还是真生成"的池子, 不是全跑模型 |

#### 第一阶段 (M9) · 接近零增量

- 5-20 款模板覆盖 Roblox / Free Fire / Minecraft / GTA V / PUBG Mobile / MLBB 等主流, 归到 3-4 类玩法
- 平台已有 [高光时刻] + [游戏 title 分类] 信号 → Encore 匹配模板, **运行时不调模型**
- Hackathon 已做 3 套 × 12 主题 = 36 组合, 生产扩到 5-20 套 × M 主题, 一次性投入
- **每路 Encore 启动增量 LLM 成本 ≈ $0**
- 灰度 / 礼物经济期都跑这一套, 不烧钱
- **劣势**: 跟主播这一波具体高光契合度有限(只能按 [游戏 × 大类场景] 粗粒度匹配), 第二阶段才做真生成

#### 第二阶段 · 基础版 ($70-72K/月)

- 4050 万月候选, **80% 走模板, 20% 真生成 = 810 万次真生成/月**
- 模型路由(详见单次成本表):
  - **80%** 用 GPT-5.4 mini / Claude Haiku 4.5(参数化玩法, 大多数场景)
  - **15%** 用 Claude Sonnet 4.6(中腰部高价值房间)
  - **5%** 用 GPT-5.5 / Claude Opus 4.8(头部房间 / 强传播 / 厂商合作)
- 模型调用约 **$55-57K/月**, 加上 $15K/月模板刷新 + 监控余量 = **$70-72K/月**
- 适用: 礼物经济刚上线, 收入还在验证, 先保证不烧穿预算

#### 第二阶段 · 放量版 (≤$100K/月封顶)

- 同样的路由, 但真生成比例提到 ~30% (约 1200 万次/月) — 给头部房间更好的契合度
- **预算闸门按日封顶**, 不靠口头承诺:月 $100K ÷ 30 ≈ 日 $3,333

| 当日预算使用率 | 系统动作 | 用户看到什么 |
|---|---|---|
| < 70% | 头部房间用 GPT-5.5 / Opus, 中腰部 Sonnet, 普通房间 mini / Haiku | 高价值房间的 Encore 更贴近刚才那波高光 |
| 70%-90% | 贵模型只给头部 + 厂商合作游戏, 其他真生成降到 mini / Haiku | 大多数体验不变, 少数普通房间回到模板 |
| > 90% | 停止普通房间真生成, 只保留模板 + 已承诺的头部场景 | 系统不超支, 用户仍能玩 Encore, 贴合度降低 |

- 适用: 厂商 CPI / 联运 / 月卡跑起来后, 主动提高头部房间的内容贴合度

#### 单次真生成成本(默认 2k 缓存 + 1k 动态输入 + 600 输出 + 15% 重试余量)

| 模型 | 输入 / 缓存 / 输出价 (per 1M token) | 单次成本 | Encore 里怎么用 |
|---|---|---|---|
| GPT-5.5 | $5.00 / $0.50 / $30.00 | **$0.0276** | 头部直播间、高价值高光、厂商合作游戏 |
| Claude Opus 4.8 | $5.00 / $0.50 / $25.00 | **$0.0242** | 跟 GPT-5.5 同层, 给最值得做精细玩法的高光 |
| Claude Sonnet 4.6 | $3.00 / $0.30 / $15.00 | **$0.0145** | 中腰部高价值房间, 质量和成本之间比较稳 |
| GPT-5.4 mini | $0.75 / $0.075 / $4.50 | **$0.0041** | 大多数真生成调用 (参数化玩法) |
| Claude Haiku 4.5 | $1.00 / $0.10 / $5.00 | **$0.0048** | 低成本生成和兜底, 高频简单场景 |
| GPT-5.4 nano | $0.20 / $0.02 / $1.25 | **$0.0011** | 分类、打分、判断是否升级到贵模型 |

价格来源:内部 ModelHub(GPT 系列已接入)+ OpenAI 官方 + Anthropic 官方价格页。

#### 回本线(按"每次高光生成"算, 不按"每个观众"算)

模型只为一个直播间高光生成 **1 份** 玩法参数, 直播间里所有观众一起玩, 成本被整场观众摊薄。 单看模型费, 一次 Enhance($0.5)就能回本:

| 模型 | 单次成本 | 回本需要几笔 $0.5 Enhance |
|---|---|---|
| GPT-5.5 | $0.0276 | 0.06 笔 |
| Claude Opus 4.8 | $0.0242 | 0.05 笔 |
| Claude Sonnet 4.6 | $0.0145 | 0.03 笔 |
| GPT-5.4 mini | $0.0041 | 0.01 笔 |
| Claude Haiku 4.5 | $0.0048 | 0.01 笔 |

启示:**小房间不值得用贵模型, 大房间或高传播高光才值得**。 这就是为什么路由系统按"房间价值 + 高光价值"分级。

#### 为什么第一阶段不直接上 LLM

1. 上线速度 — M9 内测 5-10 主播 1 周需要稳定流程, LLM 在 5s 窗口靠谱性还没验证
2. 单位成本 — 第一阶段几乎免费, 收入流还没起来时不烧 LLM 是负责任的选择
3. 可预测性 — 手工模板行为可预测, 灰度排查问题更简单

#### 短视频渲染成本(全方案共用, 次要)

- 端侧 Canvas + MediaRecorder 合成(PR #24 已跑通)= **零服务端成本**
- 生产环境若改服务端重渲: 全量 50K × 50 高光 × 3 名 = 7.5M 条/天 × 0.5-1 CPU·秒 ≈ ~$50-200/天, 相对模型成本可忽略
- 本节不包含人力 / 运营激励 / 钱包接入 — 这张表只回答"模型调用怎么在 $10 万/月内算清楚"

### 6.3 收入预估(对应 §4.3 三类收入的可量化版本)

**核心结论**:Phase 1 (Enhance 跑通) **$1.5M/月** → Phase 2 (加 CPI + 联运) **$2.0M/月** → Phase 3 (加多人玩 sponsor) **$2.1M/月**。 模型成本相对收入 **净利率 95%+**。

#### 锁定参数(跟成本测算同口径,3 轮跟 PM 校准后定)

| 参数 | 取值 | 来源 / 依据 |
|---|---|---|
| 月 Encore 触发 | **4050 万** | 跟 §6.2 成本测算同口径 |
| 直播间平均在线观众 | 25(均值) | TikTok Gaming 实际:长尾 10 + 头部几百,加权均值 |
| Encore 渗透率(观众里上手玩) | **20%** | 新颖体验 + 底部 sheet 不挤压, 取较保守 |
| → 每次 Encore 平均玩家 | **5 人** | 25 × 20% |
| **月玩家 session 总数** | **2.025 亿** | 4050 万 × 5 |
| Enhance 转化(每次玩) | **3%** | 手游 IAP 基准 hyper-casual 1-3%, Encore 取上限 |
| Enhance 单价 | **$0.5** | 一次续命定价 |
| 平台分成(主播抽 50%) | **× 50%** | LIVE 礼物分成铁律, 主播 ≥ 普通礼物 |
| 短视频实际发布率 | **10%** | 玩家可选拒发, 取保守 |
| 单条平均 vv | **400** | 参考游戏视频均值, 取低端 |
| CPI 单价 | **$1** | mobile game CPI 区间 |
| Install 转化率 | **5%** | Tier 2 国家平均, 取保守(远低于 10% 上限) |
| 联运合作厂商数 | ≤ 5 家 | 政策上限,Phase 2 初期取 2 家 |
| 联赛 sponsor 单价 | **$10K/月** | 行业小型 sponsor deal 起步价 |

#### A · 观众付费 (Enhance)

```
2.025 亿 player session × 3% 转化 × $0.5 单价 = $3.04M / 月 gross
× 50% 平台分成 = $1.52M / 月 净收
```

**A · 月净收 ≈ $1.5M**

> 第一阶段唯一 SKU。 Remix / 皮肤 / 月卡留第二阶段, 这版**不算进数字**。

#### B-1 · CPI install 漏斗(估低)

```
4050 万 触发 × 3 视频(top 3)× 10% 发布率 = 12.15M shorts / 月
× 400 vv = 4.86B 月浏览
× 0.2% 点击率 = 9.72M clicks
× 5% install 转化 = 486K install
× $1 CPI = $486K / 月
```

**B-1 · 月收入 ≈ $500K**

> 估低口径(vv 取 400 低端 + 点击 0.2% + install 5%);跑通后 CPI / vv 可拉高。

#### B-2 · 厂商联运 / 品牌联名(估低)

```
2 家中型 deal × $30K = $60K / 月
```

**B-2 · 月收入 ≈ $60K**

#### C · 多人玩(取保守)

不做月 Pass / 订阅, 只看联赛冠名 sponsor。

```
2 个 sponsor × $10K = $20K / 月
```

**C · 月收入 ≈ $20K**

> 直接收入小,主要价值在间接拉高 A 的留存(本节没算进数字)。

#### 总和:按阶段路径

| 阶段 | 时间 | 启用 SKU | **月净收** | 模型成本 | **净利率** |
|---|---|---|---|---|---|
| **Phase 1 灰度** | M9-M11 | 限量内测 (5-100 主播) | < $50K | ~$0 | — |
| **Phase 1 放量** | M11-M12 | A only (Enhance) | **$1.5M** | ~$0 | ~100% |
| **Phase 2 基础版** | M12-M14 | A + B-1 (CPI) | **$2.0M** | $72K | **96%** |
| **Phase 2 放量版** | M14+ | A + B 全(含联运) | **$2.1M** | $100K | **95%** |
| **Phase 3 长期** | M18+ | A + B + C(多人玩) | **$2.1M** | $100K | **95%** |

#### 上下限敏感度(单变量,其他不变)

| 变量 | 锁定值 | 下行情景 | 上行情景 | 对总月收入影响 |
|---|---|---|---|---|
| 每次 Encore 平均玩家 | 5 | 3 (-40%) | 8 (+60%) | ±60% |
| Enhance 转化 | 3% | 2% | 5% | A ±67% |
| Install 转化 | 5% | 3% | 10% | B-1 ±70% |
| vv per short | 400 | 300 | 500 | B-1 ±25% |

→ 最大风险/上行点在 **每次 Encore 玩家数**。 这个数字 M11 灰度 1 个月内就能锁住。

#### 没算的(诚实告知)

- 国别 ARPU 差异(东南亚 vs 北美 3-5x)— 全用均值
- 支付通道手续费(~5%)
- 退款 / 监管(~3%)
- 主播补贴 / 激励(政策决定)
- 第二阶段头部主播分成上调可能性(Brief 铁律:Encore 分成 ≥ 普通礼物)
- 短视频服务端渲染(~$50-200/天,忽略)
- 人力 / 运营 / BD 团队成本

#### 风险点

- **A 主要风险**: 5 人/Encore 能不能维持 — 跟主播质量 + Encore 体验设计 + "差一点赢"的挫败感强相关
- **B 主要风险**: 短视频 vv 跑不出来 / TikTok SDK install attribution 工程量
- **C 主要风险**: 暂未跑通的 SKU, $20K/月是占位估算

### 6.4 怎么灰度

| 阶段 | 范围 | 要验证什么 |
|---|---|---|
| **M9 内测** | 5-10 主播 × 1 周 | 触发率 / 完成率 / 主播体验是否被打扰 |
| **M10 灰度** | 100 主播 × 4 周 | 短视频生成质量 / 算法分发表现 / 付费转化 |
| **M11 礼物经济实装** | 同上灰度池 | 礼物门槛设置合理性 / ARPU 变化 |
| **M12 模板扩展 + 短视频入口** | 灰度扩到 1000 | 模板覆盖率 / 短视频流入口可行性 |
| **M13+** | 全量 | 真实成本曲线 / 第二阶段收入流 |

每个阶段必须先把上一阶段的验证数据出来, 再往下扩。 **不预设跳级**。

## 7. 第一版不解决的事(诚实承认)

Hackathon 阶段和第一版上线**不解决**的三件事:

### 7.1 单局游戏好不好玩

30 秒小游戏好玩的门槛非常高。 Helix Jump / Stack 那种"30 秒爽"是几十人团队几个月调出来的。 Hackathon 4 人 2 天产出的小游戏, 大概率**技术上对, 但不好玩**。

**应对**:

- 演示阶段不让评委自己玩 30 秒检验"好不好玩" — 演示重点是范式 + 闭环 + 平台叙事, 游戏一带而过
- 第一版上线后**专项投入 6-12 个月**做单局品质优化
- 这一节必须在飞书 review 时跟设计 / 美术对齐预期

### 7.2 Phase 2 实时生成的延迟 + 质量

§6.2 阶段 2 用 Sonnet / Gemini 实时生成 Encore 参数, 跟主播高光紧密契合 —— 但需要在 < 5s 内完成"理解高光 → 生成 JSON → 启动 Encore"的全链路。 LLM 调用本身的稳定性 + 输出质量在这个窗口内的表现, **需要工程实测验证**, 不能 hackathon 阶段假设跑得通。

阶段 1 预制模板不依赖 LLM 实时调用, 所以这个风险**不阻塞 M9 上线**, 只阻塞 M14+。

### 7.3 单一品类、单一形态

- 只做 **GTA Heist / Obby Parkour / Free Fire BR** 三套, 对标 FPS / MOBA / 吃鸡三大主流品类, 覆盖 60-70% 游戏直播(基于 TikTok gaming 内部分布粗估, 待验证)
- 只做直播形态, **不做短视频入口, 要等到 M12+**(短视频缺同时在场, 转化率会塌)

这三件事不是 Phase 1 失败, 是 Phase 1 范围。 提前划清楚预期。

## 8. 风险跟怎么缓解

| 风险 | 怎么缓解 |
|---|---|
| **观众嫌烦**: 5h × 50 高光 = 50 次弹窗 | (a) 主播 promote/skip 砍 30-50%; (b) 每场每观众最多 3-5 次弹窗; (c) 新用户首次进 LIVE 弹"是否开 Encore" opt-in。 三层叠加, 预期 ≤ 4 次/场 |
| **#Encore 标签被算法当 spam** | 服务端有质量门槛 + 完成度门槛 + 后续跟 TikTok 算法团队对齐"联名/混剪"标识 |
| **Bot 农场刷前 3** | 设备指纹 + LIVE 时长门槛 + Encore 历史指纹 |
| **主播礼物门槛设太高, 劝退观众** | dashboard 软警告 + 转化率反馈 |
| **观众法律弹窗劝退** | 友好措辞(参考 TikTok Duet 首次开通)+ 撤回路径清晰 |
| **MVP 游戏不好玩拖垮叙事** | 演示不让评委亲手玩; MVP 之后 6-12 个月专项 |
| **3-6 个月内 Twitch clone** | 靠 §5.2 三方差异化 + TikTok feed 自动回流, 技术不防 clone |
| **Phase 2 LLM 实时生成延迟 / 质量** | M14+ 之前 Phase 1 预制模板路径不依赖 LLM 实时, 隔离风险 |
